## 📌 Apresentação do Projeto

O **Turismo Consciente** é um projeto acadêmico desenvolvido por estudantes do curso de Análise e Desenvolvimento de Sistemas (ADS) da Universidade Cidade de São Paulo (UNICID).

O projeto tem como finalidade conscientizar a sociedade sobre a importância do turismo sustentável, incentivando práticas responsáveis que contribuam para a preservação ambiental, a valorização cultural, a inclusão social e a acessibilidade.

O site apresenta conteúdos educativos, iniciativas sustentáveis, informações sobre impacto ambiental, recursos multimídia e um formulário de contato.

Além da conscientização ambiental, o projeto permite aplicar conhecimentos de desenvolvimento Front-End, organização de código, acessibilidade, responsividade, versionamento e publicação de sites.

## 🎯 Objetivos do Projeto

### Objetivo Geral

Desenvolver um site informativo, responsivo e acessível sobre turismo consciente, utilizando tecnologias de desenvolvimento Front-End e promovendo a conscientização sobre sustentabilidade e impacto social.

### Objetivos Específicos

- Incentivar práticas de turismo sustentável.
- Promover a preservação ambiental.
- Valorizar comunidades e culturas locais.
- Apresentar iniciativas de impacto social positivo.
- Incentivar a inclusão e a acessibilidade no turismo.
- Desenvolver páginas utilizando HTML5 e CSS3.
- Implementar funcionalidades interativas com JavaScript.
- Aplicar conceitos de responsividade e acessibilidade digital.
- Utilizar GitHub para versionamento e colaboração.
- Publicar o projeto na internet utilizando Railway.
- Desenvolver habilidades de planejamento, documentação e trabalho em equipe.

## 👥 Público-Alvo

O site é destinado a estudantes, turistas, profissionais da área de turismo e pessoas interessadas em sustentabilidade, preservação ambiental e inclusão social.

O projeto também considera pessoas com deficiência, buscando proporcionar uma experiência de navegação acessível e organizada.

A responsividade deve ser verificada por meio de testes em diferentes resoluções e dispositivos.

## 📝 Formulário de Contato

A página `contato.html` apresenta um formulário com validação utilizando HTML5 e JavaScript.

A validação tem como objetivo verificar o preenchimento adequado dos campos antes de simular o envio.

**Importante:** nesta versão acadêmica, o formulário apenas simula o envio da mensagem.

Não existe integração com banco de dados ou serviço de recebimento de mensagens. Portanto, os dados preenchidos não são transmitidos nem armazenados em um servidor pelo formulário.

## 🚀 Como Executar o Projeto

### Execução Local

1. Acesse o repositório do projeto no GitHub.
2. Clique em `Code`.
3. Selecione `Download ZIP`.

5. Abra a pasta `site/`.

## 🌐 Hospedagem e Publicação no Railway

O Railway é a plataforma de hospedagem apresentada no roteiro acadêmico para publicar o projeto na internet.

### Passo 1 — Acessar o Railway

Entre no endereço:

https://railway.com/

Faça login utilizando a conta do GitHub.

### Passo 2 — Criar o Projeto

1. Clique em `New Project`.
2. Selecione `GitHub Repository`.
3. Autorize o Railway a acessar o GitHub.
4. Escolha o repositório oficial do Turismo Consciente.
5. Confirme a criação do serviço.

### Passo 3 — Configurar o Diretório

Como os arquivos do site estão organizados na pasta `site/`, configure o diretório principal do serviço.

No Railway:

1. Abra o serviço do projeto.
2. Acesse `Settings`.
3. Localize a configuração `Root Directory`.
4. Defina o caminho `/site`.
5. Salve a configuração.

O arquivo `index.html` deve estar diretamente dentro do diretório configurado.

Caso a plataforma não detecte automaticamente uma forma de servir os arquivos estáticos, será necessário configurar um servidor estático compatível.

### Passo 4 — Realizar o Deploy

Após configurar o projeto:

1. Verifique as configurações de build e inicialização.
2. Execute o deploy.
3. Acompanhe o andamento da publicação.
4. Consulte os logs em caso de erros.
5. Confirme que o serviço está em execução.

### Passo 5 — Gerar o Endereço Público

1. Abra o serviço no Railway.
2. Acesse `Settings`.
3. Localize `Networking`.
4. Entre em `Public Networking`.
5. Clique em `Generate Domain`.
6. Copie o endereço público gerado.
7. Abra o link no navegador.

O Railway poderá disponibilizar um endereço terminado em `.up.railway.app`.

**Endereço público do site:** Pendente de confirmação após o deploy.

### Passo 6 — Atualizações Automáticas

Depois de configurar corretamente a integração com o GitHub, novas alterações enviadas à branch configurada para deploy poderão iniciar uma nova publicação automaticamente.

Isso permite manter o site atualizado sem precisar reenviar manualmente todos os arquivos.

## 🌍 Publicação Alternativa — GitHub Pages

Como alternativa ao Railway, o projeto também pode ser publicado utilizando o GitHub Pages.

Para isso:

1. Acesse o repositório no GitHub.
2. Entre em `Settings`.
3. Selecione `Pages`.
4. Em `Build and deployment`, escolha `Deploy from a branch`.
5. Selecione a branch `main`.
6. Escolha a pasta `/(root)` ou `/docs`, conforme a organização dos arquivos.
7. Clique em `Save`.

**Observação:** o GitHub Pages não permite selecionar diretamente a pasta `/site` nesse modo. Para utilizar essa opção, seria necessário reorganizar os arquivos ou configurar um fluxo de publicação com GitHub Actions.

O Railway permanece como a plataforma de referência para a atividade.

## 💰 Orçamento de Hospedagem e Domínio

A atividade acadêmica prevê uma pesquisa comparativa de hospedagem e domínio.

O levantamento deve considerar três provedores de hospedagem e três opções de domínio.

### Critérios de Comparação

- Preço mensal e anual.
- Custo de registro do domínio.
- Custo de renovação.
- Recursos de hospedagem.
- Limites de tráfego e armazenamento.
- Disponibilidade de HTTPS.
- Integração com GitHub.
- Suporte técnico.
- Possibilidade de banco de dados.
- Políticas ambientais e sustentabilidade.

Os valores devem ser consultados nos sites oficiais dos provedores e registrados com suas respectivas fontes e datas de pesquisa.

A análise deverá apresentar uma justificativa para a escolha da solução de hospedagem utilizada.

### Testes de Responsividade

- Testar o site em computadores.
- Verificar a apresentação em tablets.
- Testar a navegação em smartphones.

### Testes de Acessibilidade

https://validator.w3.org/
